# 外科實習整合平台

GitHub Pages 提供統一入口，Supabase Edge Function 提供助教授權與服務整合。

## 本階段範圍

- 選科查詢：即時讀取既有選科系統，保留學生選科、登入及審核流程。
- 配對核對與評分：沿用同一份院內配對及評分紀錄，修改直接寫回既有選科服務，無重複名單。
- 核心講堂：學生可由本平台作答；沿用原題庫、固定抽題、收卷時間及交卷紀錄，舊連結繼續有效。
- 助教管理：沿用選科助教帳號，查看逐場講堂成績及學生整合明細。
- 完整講師後台、題庫審閱及匿名問卷統計仍使用原講堂管理碼，可由平台連結進入。

尚未搬移學生選科／學藝審核流程。已加入 OSCE、護照完成率與實習總成績；講堂學期彙總規則尚未定義。

## 資料與權限

公開 GitHub 僅保存程式，不保存正式學生名單、配對、評分、題庫答案或管理碼。只發布 web/。前端不保存密碼或登入票證到 localStorage/sessionStorage，頁面重新整理後須重新登入。

新函式 surgery-clerkship-portal：

- 公開 catalog 僅回傳場次名稱與時程。
- 助教登入轉送原選科系統驗證，密碼不記錄、不保存。
- 原系統工作階段包在 AES-GCM 加密的短效票證內，兩小時到期；每次操作再向原系統驗證權限。原帳號停用或工作階段失效會被拒絕。
- grade-save 與 grade-history 僅接受原系統已存在的學生實習紀錄，保留原本的版本衝突與修改紀錄。
- 講堂管理先完成助教驗證，再委派至既有評量邏輯；學生端仍使用原測驗 API，不取得管理權限。
- Supabase service_role 僅存在 Edge Function 環境，不在網站或 Git 中。

目前系統依賴原選科服務供應名單、助教驗證及醫師評分儲存；此為第一階段整合，並非完整資料庫搬遷。原服務中斷時，查詢與登錄會明確回報失敗，不能改用過期副本。講堂學生端可獨立運作。

## 發布與驗證

`npm test`、`npm run check`；`npm start` 在 127.0.0.1:4180 提供靜態預覽。

將 server/index.ts、server/deno.json、server/*.mjs 與 web/score-rules.mjs 依相對路徑部署為 Supabase Edge Function surgery-clerkship-portal。verify_jwt=false，由函式內部加密票證及原站助教工作階段實作認證。

僅將 web/ 發布到 GitHub Pages。現有 core-surgery-quiz 專案、函式、題庫與成績不修改。部署不建立任何正式配對或測試成績。

## 擴充方向

後續可另行搬移學生選科與審核，再加入已確認的講堂學期計分規則。切換選科資料來源前須保留備份、比對筆數並明確指定唯一寫入來源。

## OSCE、護照與實習總成績

學生整合成績可登錄縫合與換藥（各 0–100 分，可留白）。OSCE 平均＝（縫合＋換藥）÷2，加權 20%；加上醫師平均×80%，得到扣分前小計。護照完成率可填 0–100%；低於 90% 從小計扣 10 分，等於或高於 90% 不扣分。實習總成績＝小計−護照扣分，不另加未定義的零分下限。缺任一必要分數或完成率時不產生總成績；只在顯示時保留兩位小數，計算不先四捨五入。

OSCE 與護照完成率儲存在 Supabase clerk_osce_scores；以學號、梯次及完整實習起迄日區隔，月份篩選不改變計算範圍。實習起迄日或梯次變動會形成新紀錄，須重新核對。clerk_osce_history 保留異動前後、員編及時間。資料表啟用 RLS，公眾及一般登入角色無權讀寫；只有經原站助教工作階段驗證的 Edge Function 可操作。save_clerk_assessment 在同一交易內保存分數、完成率和歷程，並拒絕舊版本覆寫。

資料庫建立腳本：依序套用 database/osce.sql 與 database/passport.sql（已部署）；部署函式時入口為 server/index.ts，匯入設定為 server/deno.json，須一併提供 web/score-rules.mjs。

護照完成率不先四捨五入再判定（例如 89.9999% 仍扣 10 分），畫面保留輸入的完成率。舊版 OSCE 儲存介面仍可使用，僅更新 OSCE，保留既有護照完成率；新版 assessment-save 必須明確傳入完成率或 null。兩者共用版本檢查與交易鎖。
