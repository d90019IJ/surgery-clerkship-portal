# 外科實習整合平台

GitHub Pages 提供統一入口，Supabase Edge Function 提供助教授權與服務整合。

## 本階段範圍

- 選科查詢：即時讀取既有選科系統，保留學生選科、登入及審核流程。
- 配對核對與評分：沿用同一份院內配對及評分紀錄，修改直接寫回既有選科服務，無重複名單。
- 核心講堂：學生可由本平台作答；沿用原題庫、固定抽題、收卷時間及交卷紀錄，舊連結繼續有效。
- 助教管理：沿用選科助教帳號，查看逐場講堂成績及學生整合明細。
- 完整講師後台、題庫審閱及匿名問卷統計仍使用原講堂管理碼，可由平台連結進入。

尚未搬移學生選科／學藝審核流程。已加入 OSCE、護照完成率與實習總成績；核心講堂依各學生應考名單計算筆試平均，已截止未交卷計 0 分。

## 資料與權限

公開 GitHub 僅保存程式，不保存正式學生名單、配對、評分、題庫答案或管理碼。只發布 web/。前端不保存密碼或登入票證到 localStorage/sessionStorage，頁面重新整理後須重新登入。

新函式 surgery-clerkship-portal：

- 公開 catalog 僅回傳場次名稱與時程。
- 助教登入轉送原選科系統驗證，密碼不記錄、不保存。
- 原系統工作階段包在 AES-GCM 加密的短效票證內，兩小時到期；每次操作再向原系統驗證權限。原帳號停用或工作階段失效會被拒絕。
- grade-save 與 grade-history 僅接受原系統已存在的學生實習紀錄，保留原本的版本衝突與修改紀錄。
- 講堂管理先完成助教驗證，再委派至既有評量邏輯；學生端仍使用原測驗 API，不取得管理權限。
- Supabase service_role 僅存在 Edge Function 環境，不在網站或 Git 中。

目前系統依賴原選科服務供應名單、助教驗證及醫師評分儲存；此為第一階段整合，並非完整資料庫搬遷。原服務中斷時，查詢與登錄會明確回報失敗，不能改用過期副本。講堂學生端可獨立運作。

## OSCE、護照與實習總成績

學生整合成績可登錄縫合與換藥（各 0–100 分，可留白）。OSCE 平均＝（縫合＋換藥）÷2，加權 20%；加上醫師平均×80%，得到扣分前小計。護照完成率可填 0–100%；低於 90% 從小計扣 10 分，等於或高於 90% 不扣分。實習總成績＝小計−護照扣分，不另加未定義的零分下限。缺任一必要分數或完成率時不產生總成績；只在顯示時保留兩位小數，計算不先四捨五入。

OSCE 與護照完成率儲存在 Supabase clerk_osce_scores；以學號、梯次及完整實習起迄日區隔，月份篩選不改變計算範圍。實習起迄日或梯次變動會形成新紀錄，須重新核對。clerk_osce_history 保留異動前後、員編及時間。資料表啟用 RLS，公眾及一般登入角色無權讀寫；只有經原站助教工作階段驗證的 Edge Function 可操作。save_clerk_assessment 在同一交易內保存分數、完成率和歷程，並拒絕舊版本覆寫。

資料庫建立腳本：依序套用 database/osce.sql 與 database/passport.sql（已部署）；部署函式時入口為 server/index.ts，匯入設定為 server/deno.json，須一併提供 web/score-rules.mjs。

護照完成率不先四捨五入再判定（例如 89.9999% 仍扣 10 分），畫面保留輸入的完成率。舊版 OSCE 儲存介面仍可使用，僅更新 OSCE，保留既有護照完成率；新版 assessment-save 必須明確傳入完成率或 null。兩者共用版本檢查與交易鎖。

## 逐位核對操作

配對核對與評分預設顯示一位學生的完整外科安排，可直接修改老師、狀態與分數，下方同步輸入 OSCE／護照並試算總成績。全班總覽顯示已儲存的核對進度、缺分狀態與總成績。篩選決定學生名單，不會截斷該學生的實習科別。

此改版僅調整前端，沿用原紀錄及儲存介面，不搬移、不清空正式資料。只有變動或明確重新核對的紀錄會送出；未改動的空白項目也不建立紀錄。儲存並下一位會等所有變動成功才切換；部分失敗時保留已成功項目及剩餘草稿，重試只處理未完成項目。更換已有分數的老師會清除畫面上的舊分數，使用者另填新分數後，依原服務規則分兩次保存並保留歷程。

草稿只暫存在目前頁面，切換學生、篩選或總覽時保留；重新整理、重新載入或離開頁面前有未儲存提醒，登出後清除。既有版本衝突檢查維持有效。

配對原因可點選「單位安排」「原安排老師不在」「其他」，只有「其他」需要輸入非空白原因。老師與原選不同時必須選擇原因。預設選項直接存回原本 note 欄位，不修改儲存格式；既有自由文字完整保留於「其他」，不因載入畫面而重寫。切換選項時保留本頁的其他原因草稿；「清除選擇」為明確清除原因，須儲存才生效。

入口及管理頁使用霧紫灰配色，主要表格與輸入字體放大至 18px。粉圓（Huninn）由 Google Fonts 載入，使用 display=swap；無法載入時使用本機正黑體等中文字體，確保仍可操作。樣式位於 web/lavender.css，與成績資料及計算規則分離。

## 全班快速篩選與核心講堂總成績

「全部」「只看尚未核對」「只看缺分數」依目前搜尋、梯次、月份及狀態顯示人數。尚未核對包含原本未核對及選科異動待重新核對；確認未配對屬已核對。缺分數包含未能採計的醫師評分、縫合、換藥及應考講堂異常分數；護照完成率缺漏另列提醒。0 分是有效分數，未來實習缺分不代表逾期。篩選與切換不清除草稿。

核心講堂以學號連結應考名單，所有應考場次等權平均；已截止未交卷採 0 分，未截止或未設定截止時間不先計零。尚有待計場次時顯示「待結算」及已可計分場次的目前平均，全部場次可計分才顯示總成績。問卷是否完成不影響筆試計分。沒有應考名單時不產生零分或總成績；未列應考名單的交卷仍可在明細查看，但不納入平均。講堂統計獨立於外科實習梯次與月份篩選。

講堂總成績顯示在全班總覽、逐位核對表、學生整合成績及逐堂明細，整合成績匯出包含總成績、目前平均、應考／已計／未交卷計零／待計場次。截止判斷採最近資料載入的伺服器時間，重新載入會取得最新交卷與判斷時間；避免停留中的舊頁面因時間經過而把尚未載入的交卷誤判零分。這些是讀取後計算，不新增或修改原始交卷及成績紀錄。

## 待提醒名單與每週人工核對（不寄信）

「待提醒名單」依已儲存資料顯示納入外科、已確認配對、院內實際老師非空白、沒有選科異動且分數為 null／未設定的項目。0 分視為已評分；異常分數不當作缺分。以各段實習結束日為包含當天，台北時間第 8 天 00:00 起列入（例：11/6 結束，11/14 起列入）。查詢及每次保存都重新驗證原選科系統助教登入、取得最新配對資料，採伺服器時間判斷。

勾選「確認仍未評分」立即保存；取消勾選撤回確認。確認從保存時間起有效七天，超過七天需重新勾選；老師、期間、科別、原選老師或來源紀錄版本改變時，舊確認不再有效，紀錄仍保留。表格可依老師／學生搜尋、篩選待核對與已確認、查看核對時間與登錄員編、展開歷程，以及前往逐位核對表補登分數。名單不會修改原配對、醫師分數、OSCE 或護照資料。

新增資料表為 clerk_reminder_reviews 與 clerk_reminder_review_history，SQL 定義保存在 database/reminder-reviews.sql，已套用雲端 migration clerk_reminder_reviews。兩表啟用 RLS 並撤銷 public、anon、authenticated 存取；只有後端 service_role 可讀寫。save_clerk_reminder_review 為 security invoker，版本檢查、每項目交易鎖和附加歷程在同一交易內完成。前端只能提供勾選與預期版本，核對者由驗證後的助教身分決定，時間由資料庫決定。測試 tests/reminder-storage.sql 使用合成資料並在最後 rollback。

待提醒名單的勾選只保存核對，不觸發寄信。平台手動寄信見下方「學校信箱連結」。目前沒有寄信佇列或定時排程。部署 surgery-clerkship-portal Edge Function 時需包含 web/reminder-rules.mjs。

## 老師 Email 通訊錄與合併提醒預覽（不寄信）

老師 Email 通訊錄從已納入外科的原選老師與院內實際配對帶出姓名及科別，直接填寫第一個信箱、選填第二個信箱與院內編號／識別註記，逐筆儲存。通訊錄獨立保存，不變更配對、分數、護照或原核對紀錄。草稿在切換頁籤與篩選時保留，離開頁面、重新載入或登出前提醒。

老師身分以通訊錄 UUID 區隔，以正規化的姓名＋科別明確連結。相同老師跨科別可選擇共用已存通訊錄；同名不同人可另建。不得僅依相同 Email 自動合併。現有來源未提供可靠的老師 ID，因此同科同名仍須人工辨識，不能當成院內身分自動驗證。更換院內老師後使用新配對查找通訊錄。

合併提醒預覽重新取得來源資料，僅納入已到提醒日且仍在七天核對有效期內的項目。以通訊錄身分分組，每位老師一封；相同學生合併一列，保留每段實習科別、Course、期間與梯次。未連結通訊錄和缺信箱明確列示。預覽顯示資料時間，更新按鈕取得最新狀態。沒有信件本文、寄信按鈕、寄信佇列或郵件排程，mailEnabled 維持 false。

資料表 clerk_teacher_contacts、clerk_teacher_bindings、clerk_teacher_contact_history 與 save_clerk_teacher_contact 由 database/teacher-contacts.sql 建立；RLS、角色權限、版本檢查、交易鎖及附加歷程與既有後端一致。SQL 回滾測試在 tests/contact-storage.sql。部署 Edge Function 時一併包含 web/contact-rules.mjs。

每位老師可保存 Email 1 與 Email 2；未來同一封合併提醒同時寄到這兩個信箱。第二個信箱可留白，填寫時必須有第一個信箱且兩者不同；伺服器驗證每欄為單一地址，拒絕多收件人字串與換行。預覽依通訊錄 UUID 分組，recipients 陣列包含兩個地址並去重，仍無寄信功能。舊前端未送 secondaryEmail 時保留既存第二個信箱；明確送空字串才清除。新增欄位與交易函式見 database/teacher-contact-emails.sql，雙信箱、舊介面保留及歷程測試見 tests/contact-emails-storage.sql。正式匯入資料與個人信箱不可提交到 GitHub。

## 本批寄送確認與寄送紀錄（2026-11-06）

助教先在待提醒名單保存「確認仍未評分」，再到本批寄送確認選取老師建立批次。後端依最新來源、有效核對與老師通訊錄產生每位老師一封的固定信件快照，包含兩個收件信箱、主旨、學生明細、完整 HTML 與來源版本。逐封勾選後保存本批確認；此操作不觸發寄信；使用者須在平台連結學校信箱、核對摘要並按最後的「確認寄出」。預定寄件信箱為使用者指定的學校信箱，實際寄送前仍須驗證登入帳號。

批次快照不可改寫；取消仍保留原文和確認歷程。信箱、對應、配對、分數、姓名、核對版本或七天有效期改變時，顯示需重新核對，不能再次確認過時內容。建立與確認前重新讀取原系統，資料庫另驗證本地版本並以交易鎖、唯一 request_id、批次 revision 防止重複與覆蓋。原成績、護照與通訊錄不會被批次功能修改。

資料表 clerk_reminder_batches、clerk_reminder_batch_history、clerk_reminder_deliveries 全部啟用 RLS 並限制為後端存取。寄送結果僅由後端手動寄信流程寫入；確認紀錄不會被當作已寄出。每封寄送前重新驗證來源、聯絡人、核對狀態與批次版本，先保留處理紀錄，再呼叫 Gmail。沒有草稿、排程或自動重試。

後端部署需加入 server/reminder-batches.mjs 與 web/reminder-letter.mjs。SQL 見 database/reminder-batches.sql；合成資料回滾測試見 tests/batch-storage.sql。前端新增 web/batch-ui.mjs。寄送紀錄提供完整批次內容與操作者／時間；歷史含學生與老師私人資料，不可匯出或提交到公開 GitHub。

「待提醒名單」支援「全選確認仍未評分」，只處理目前搜尋及核對進度篩選顯示的待核對項目。已在七天有效期內的確認不重複更新。按下後沿用逐筆核對端點依序保存，每筆皆重新驗證配對、評分與版本；畫面顯示進度並鎖定操作。任何一筆錯誤或結果不明即停止，保留前面成功紀錄並顯示尚未處理數量，不自動重試；登入失效後停止。此操作不建立信件、不寄信。


## 學校信箱連結與手動寄信（2026-11-06）

2026-11-07 已在學校組織 nycu.edu.tw 建立 Google Cloud 專案 Surgery Clerkship Mail（surgery-clerkship-mail），啟用 Gmail API，OAuth 目標對象設為內部。專案未連結計費帳戶，未啟用免費試用。Web application 用戶端為 Surgery Clerkship Portal Web，Authorized JavaScript origin 僅 https://d90019ij.github.io（不含路徑）；GIS token model 不需重新導向 URI。公開 client ID 存於 server/mail-config.mjs；未儲存或使用 client secret。空 client ID 時所有寄送端點關閉。實際登入與 Google 信箱授權仍須由使用者確認，不測試寄真實郵件。
